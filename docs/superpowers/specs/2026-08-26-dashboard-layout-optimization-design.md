# 控制台概览布局优化设计规范 (Dashboard Layout Optimization Design)

## 1. 概述与背景 (Overview)

当前 Gemini Proxy Web 控制台概览（Dashboard）采用 4 张并排 SVG 趋势图 + 底部 2 栏矩阵的纵向长页面布局。在日常运维与使用中，存在以下问题：
- **空间利用率不高**：4 张图表占据大面积垂直高度，必须多次向下滚动才能查看“模型性能与分布矩阵”和“系统运行时配置”。
- **信息层级不够直观**：运维人员最关心的“模型调用比例与性能排行”处于页面最底层，无法在打开概览的首屏（Above-the-fold）一览无余。

本次优化重构目标：
- 采用**黄金 6:4 左右分栏结构**，将**模型性能与分布矩阵**上移至首屏右上侧核心视觉区域；
- 左侧整合流量趋势与延迟趋势核心图表，支持跨图表同步十字准线联动；
- 右侧垂直堆叠“模型性能矩阵”与“系统运行时参数矩阵”；
- 底部保留完整的多模型并发时间序列分布图，兼顾宏观把握与深度分析；
- 保持 Linear / Dark 风格与中英双语国际化支持。

## 2. 页面结构与栅格系统 (Layout & Grid System)

### 2.1 整体网格层次

页面容器限定最大宽度 `max-w-7xl mx-auto`，自上而下分为 4 个主要层级：

```
+-----------------------------------------------------------------------------------+
| 1. Header & Controls (标题 + 版本标签 + 在线状态 + 时间范围切换: Today/6h/12h/24h/48h)  |
+-----------------------------------------------------------------------------------+
| 2. KPI Cards (4 栏: 服务器健康度 | 总请求数 | 平均延迟 | 成功率与错误比)               |
+-------------------------------------------------+---------------------------------+
| 3. 首屏黄金主体区 (左右 6:4 双栏)                  |                                 |
|   [左侧 60% 监控视窗 (lg:col-span-7 / xl:8)]     | [右侧 40% 核心矩阵 (lg:col-span-5 / xl:4)] |
|   - 流量与成功率综合趋势图 (Volume & Ratio)       | - 【置顶】模型性能与分布矩阵     |
|   - 模型平均延迟趋势图 (Model Latency)            |   (模型分布/进度条/平均延迟/占比)  |
|                                                 | - 系统运行时参数矩阵            |
|                                                 |   (Log Level, Timeout, Mode...) |
+-------------------------------------------------+---------------------------------+
| 4. 底部进阶分析区 (全宽 100%)                                                       |
|   - 多模型调用量时间序列分布图 (Model Call Distribution)                            |
+-----------------------------------------------------------------------------------+
```

### 2.2 响应式断点规则
- **Desktop (≥ 1024px, `lg:`)**：
  - 首屏严格执行左右 6:4 分栏（左 7 栏 / 右 5 栏 或 左 8 栏 / 右 4 栏），左右高度对称协调。
- **Tablet & Mobile (< 1024px)**：
  - 自动降级为单列垂直流；
  - 顺序优先保证“模型性能矩阵”排在首屏 KPI 卡片下方，使得移动端同样能第一眼看到模型调用情况。

## 3. 详细组件与交互设计 (Components & Interactions)

### 3.1 KPI 统计指标栏 (KPI Summary Row)
- **卡片 1：服务器状态**
  - 在线状态呼吸灯 (`animate-ping`)、Uptime 运行时长、健康度 `HEALTHY` 标签。
- **卡片 2：总请求量 (Total Transactions)**
  - 时间区间内的请求累计计数（带逗号格式化）、时间区间标签。
- **卡片 3：平均响应延迟 (Average Latency)**
  - 毫秒数展示、上游超时阈值提示 (`UPSTREAM_TIMEOUT_MS`)。
- **卡片 4：成功与错误比率 (Success vs Errors)**
  - 成功数 / 错误数对比、错误率百分比徽章（根据是否有错误动态切换红/绿高亮）。

### 3.2 首屏左侧：双主图监控视窗 (Core Metric Charts)
- **图表 1：请求流量与成功状态趋势图 (Volume Trend)**
  - SVG 面积填充 (`linearGradient`) + 平滑折线；
  - 悬浮时显示垂直虚线准星与毛玻璃 Tooltip，展示当前时间节点的 Total / Success / Error 及微型比例条。
- **图表 2：多模型响应延迟分析图 (Latency Trend by Model)**
  - 各活跃模型独立颜色折线，配合点位采样指示；
  - 支持多模型延迟同轴比对；
  - 与图表 1 共享 `hoveredIndex`，鼠标悬浮时双图同步展示时间准星。

### 3.3 首屏右侧：置顶模型性能矩阵与运行参数 (Performance & Runtime Matrices)
- **组件 A：模型性能与分布矩阵 (Model Performance Matrix - 置顶)**
  - 按模型调用总量降序（Desc）自动排列；
  - 每行包含：模型颜色圆点、完整模型名称、平均响应时间标签（`~X ms`）、请求总数、占比进度条及百分比；
  - 模型较多时支持局部滚动，保持与左侧高度一致；
  - 空状态友好占位。
- **组件 B：系统运行时参数矩阵 (System Runtime Matrix)**
  - 2x3 网格卡片：`LOG_LEVEL`、`UPSTREAM_TIMEOUT`、`SYSTEM_ROLE_TO_INSTRUCTION`、`LOG_RETENTION_DAYS`、`TIME_ZONE`、`COUNT_TOKENS_MODEL`；
  - 字体采用等宽字体 `font-mono`，关键布尔值与模式高亮展示。

### 3.4 底部全宽：模型并发分布趋势 (Model Distribution Trend)
- 保留时间轴全量模型调用分布折线图，用于深入追溯特定模型在各时间段的突增与波动。

## 4. 国际化与设计系统 (i18n & Theme)

### 4.1 颜色规范 (Color Palette)
- 页面背景：`#090A0F`
- 卡片背景：`#0F1118/90`，边框 `border-white/[0.08]`，悬停发光 `hover:border-indigo-500/30`
- 状态指示：Emerald 成功色 (`#10B981`)、Indigo 品牌主色 (`#6366F1`)、Purple 延迟分析色 (`#A855F7`)、Rose 告警色 (`#F43F5E`)
- 多模型色系映射：`['#6366F1', '#38BDF8', '#10B981', '#F59E0B', '#EC4899', '#A855F7', '#14B8A6']`

### 4.2 语言文案对照 (i18n)
- 所有标题、标签、时间区间与 Tooltip 文本均从 `src/i18n/locales/zh.ts` 与 `src/i18n/locales/en.ts` 中读取，保证双语完整一致。

## 5. 验证与测试标准 (Verification & Testing)

1. **视觉与交互测试**：
   - 检查在桌面端（1440px / 1920px）下 6:4 左右分栏布局与高度协调性；
   - 检查在移动端（< 768px / 1024px）下自适应堆叠顺序是否正确（性能矩阵优先展示）；
   - 检查时间范围切换（Today / 6h / 12h / 24h / 48h）时数据重载与图表重绘；
   - 检查多图表间悬浮联动（Tooltip 与 Crosshair）定位是否精准。
2. **构建与单元测试**：
   - 运行 `npm run build:frontend` 验证 Vite + TypeScript 编译无任何类型与语法错误；
   - 运行 `npm test` 验证后端与代理转换测试套件全部通过。
