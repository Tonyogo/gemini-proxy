# 终端文本选择与高阶复制交互优化设计规范

- **状态**: Approved
- **日期**: 2026-09-08
- **模块**: `frontend/src/components/WebTerminalView.tsx`, `frontend/src/i18n/locales/zh.ts`, `frontend/src/i18n/locales/en.ts`

---

## 1. 背景与核心问题

### 1.1 现状与痛点
1. **桌面 Web 端选中文本难以直接复制**：
   - 当终端运行命令或交互式会话（例如进入 Claude CLI、Vim 或 htop 时，终端开启了 Alternate Buffer 或鼠标事件监听），用户在终端屏幕中用鼠标划选文字后，顶栏并没有显式的高亮复制入口；
   - 必须通过双击触发系统原生的全局选择框，底层的复制按钮才生效，交互割裂且不符合常规命令行终端习惯。
2. **移动端选择模式浮层臃肿换行、显示错乱**：
   - 移动端进入选择模式后，原顶部悬浮工具栏硬塞了“划选中”、“全选当前屏”、“清除选择”、“复制”、“完成”等 5 个长文字按钮，在手机屏幕（宽度 360px ~ 390px）下直接折成 2~3 行，导致边框错位、重叠挤压，视觉非常凌乱。

### 1.2 优化目标
1. **桌面端**：
   - **选区悬浮小气泡**：鼠标在终端选中文本后，在选区右上方自动弹出轻量精致的 `[ 📋 复制 ]` 气泡，点击即复制；
   - **顶栏复制按钮联动**：在桌面端顶栏操作区常驻快捷复制按键，有选区时立即高亮变色并指示已选字符数。
2. **移动端**：
   - **单行微胶囊重构**：将顶部选择模式浮层彻底重构为 iOS 风格的毛玻璃紧凑单行胶囊，精简文字、图标化呈现、显示已选字数，全机型严禁换行。

## 2. 详细设计与交互规范

### 2.1 桌面端：选区悬浮微气泡 (Selection Floating Bubble)

```
+-------------------------------------------------------------+
| $ claude chat                                               |
| > Hello! I am Claude. How can I help you?                   |
|   |.....................................|                   |
|   | How can I help you?                 | [ 📋 复制 (19字) ] | <- 选区末端右上角微气泡
|   |.....................................|                   |
+-------------------------------------------------------------+
```

1. **触发与坐标计算**：
   - 监听终端容器的 `mouseup` / `selectionchange` 事件；
   - 当 `term.hasSelection()` 为 true 时，提取最后选中行与列的屏幕像素坐标 `(x, y)`，将气泡定位在选区右上角；
   - 边界溢出保护：气泡右侧超出容器时自动向左靠齐，顶部靠近边框时自动沉降至选区下方。
2. **点击行为**：
   - 点击气泡触发 `handleCopySelection()`，将选中字符写入剪贴板；
   - 复制成功后弹出轻量 Toast（`已复制到剪贴板`），清空选区并平滑淡出气泡。
3. **顶栏复制按钮同步**：
   - 在桌面端控制栏（字号、重连按钮左侧）增加常驻的 `[ 📋 复制 ]` 按钮；
   - 无选区时：半透明禁用态；有选区时：高亮紫色发光态，点击同样可快速复制。

---

### 2.2 移动端：紧凑单行毛玻璃胶囊 (Mobile Compact Capsule)

```
+---------------------------------------------------------------------------------+
|  [ ✏️ ]  |  [ ⬚ 全选 ]  [ 📋 复制 42字 ]  |  [ ✕ 取消 ]  [ ✓ 完成 ]            |
+---------------------------------------------------------------------------------+
```

1. **排版尺寸与防换行**：
   - 容器：`flex items-center gap-1 sm:gap-1.5 px-2 py-1 rounded-2xl bg-[var(--bg-surface)]/95 backdrop-blur-xl border border-indigo-500/30 shadow-2xl z-30 select-none whitespace-nowrap max-w-[95vw]`；
   - 总宽度控制在约 260px~280px，留出充分边距，绝对不发生换行。
2. **按钮精简规范**：
   - **状态标识**：仅保留精致图标 `TextSelect`，节省宝贵横向宽度；
   - **全屏选择**：文案由 `全选当前屏` 缩减为精炼的 `[ ⬚ 全选 ]`（`px-2 py-0.5 text-[11px]`）；
   - **核心复制键**：
     - 未选时：灰态 `[ 📋 复制 ]`；
     - 选中有内容时：点亮高亮靛蓝渐变背景 `[ 📋 复制 18字 ]`；
   - **清除与退出**：
     - 包含紧凑的 `[ ✕ 清除 ]`（仅在有选区时显示，节省空间）；
     - 右侧紧凑的 `[ ✓ 完成 ]` 绿色按键，点击保存状态并收起选择模式。

## 3. 自动化测试与验证标准

1. **测试断言 (`tests/terminalSelectionCopy.test.ts`)**：
   - 验证选区变化时 `hasSelection` 状态正确更新；
   - 验证移动端顶部选择浮层样式类包含单行防换行约束（`whitespace-nowrap`、`max-w-[95vw]` 等）；
   - 验证顶栏复制按钮与悬浮气泡在不同平台（移动/桌面）下的呈现逻辑；
   - 验证文本复制回退机制（Clipboard API 降级到 document.execCommand）。
2. **全量构建验证**：
   - 运行 `npm test` 保证所有自动化测试通过；
   - 运行 `npm run build:frontend` 保证 Vite 生产编译零错误。
