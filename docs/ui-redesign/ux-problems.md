# 当前系统交互体验 (UX) 痛点深度剖析 (UX Problems)

本文件系统性审视当前前端系统中存在的交互摩擦、可用性缺陷、视觉不一致、移动端适配瓶颈及性能短板，为后续重构方案提供明确的问题依据。

---

## 1. 痛点严重级别概览

| 问题编号 | 痛点模块 | 核心问题概括 | 严重等级 |
| :--- | :--- | :--- | :--- |
| **UX-01** | 全局路由与导航 | 缺少真实 URL 路由与深层链接，刷新丢失深层上下文，无法分享具体日志/账号 | **High** |
| **UX-02** | 账号与凭据管理 | 巨型组件（1000+行），底部内嵌轮询日志造成性能与认知混淆，缺乏多模型配额直观可视化 | **High** |
| **UX-03** | 请求日志与排障 | 缺乏高级过滤（按耗时、Token量、模型名称筛选），移动端左右分栏体验割裂，无导出/批量清理能力 | **High** |
| **UX-04** | 终端与系统观测 | Accounts 页面内嵌终端日志与 Terminal 专属页日志功能重复且获取机制不同（轮询 vs SSE） | **Medium** |
| **UX-05** | API 调试操场 | 缺乏请求历史记录保存能力，调试结果在刷新后丢失，缺乏参数可视化配置面板 | **Medium** |
| **UX-06** | 翻译工作台 | 多模型结果对比排版在小屏幕下宽度挤压，缺乏差异对比（Diff）或盲测评分机制 | **Low-Medium** |
| **UX-07** | 视觉规范与反馈 | 空状态插画缺失，错误提示形式多样（Banner / Toast / Red Text），无全局反馈统一体系 | **Medium** |
| **UX-08** | 浅色模式适配 | 部分 Monaco 编辑器与第三方滚动条在深浅色切换时存在微弱对比度不协调与边框硬切 | **Low** |

## 2. 深度痛点详细剖析

### UX-01: 全局路由缺失与状态不可持久化 (No URL-First Routing)
- **现象描述**：
  - 目前所有页面切换依赖 `activeTab` 内存状态 + `localStorage`。
  - 用户在 `LogsView` 找到了一条关键的 `500 Internal Error` 交易日志，准备发给同事协助排查，但无法从浏览器地址栏复制出类似于 `https://proxy.domain.com/logs/2026-09-03/15/tx-xxx.json` 的具体 URL。
  - 用户在 `AccountsView` 设置了关键词 `vip` 并且筛选了 `status=ACTIVATED`，刷新页面后，关键词丢失，回到了默认未筛选状态。
- **影响**：无法多人协作共享排障现场，单人操作在误触刷新或移动端返回时体验极差。

---

### UX-02: 账号管理页面的认知负荷与性能消耗 (Accounts Cognition & Polling Overhead)
- **现象描述**：
  - **职责过载**：`AccountsView.tsx` 既负责管理高价值的 OAuth 凭据文件，又在页面底部强行塞入了一个“终端日志（轮询模式）”。
  - **轮询性能隐患**：当用户展开底部终端日志时，页面启动 `setInterval(..., 3000)` 每 3 秒全量调用一次 `/api/admin/accounts/status`。这导致即便用户只是想看日志，也会无谓地重新计算和反序列化上百个账号的配额和凭据元数据。
  - **用量可视化体验简陋**：每个账号右侧的模型用量依赖悬浮 Popover 或手风琴展开。Popover 会因为页面滚动或边界遮挡而闪烁，且缺少多模型消耗的柱状对比。

---

### UX-03: 请求日志多维排障能力的局限 (Logs Diagnostic Limitations)
- **现象描述**：
  - **时间分层割裂**：目前只能强制先选“日期”，再选“特定小时”，然后再在左侧列表滚动翻页。如果一个长事务或调试跨越了整点（例如 14:58 到 15:05），用户必须频繁切换小时下拉框。
  - **缺少高维过滤字段**：排障人员往往需要找：
    1. “耗时超过 5000ms 的长请求”；
    2. “包含特定模型如 `gemini-pro-latest` 的请求”；
    3. “发生过 Thinking 思考模式的请求”；
    当前界面仅支持状态码（2xx/4xx/5xx）和文件名模糊搜索，无法直接按字段过滤。
  - **移动端分栏体验断层**：在小屏下，日志列表与详情采用遮罩式弹出，返回按钮与标题层叠，缺乏平滑的抽屉（Drawer）过渡动效。

---

### UX-04: 重复日志系统的架构矛盾 (Terminal Logs Architectural Conflict)
- **现象描述**：
  - 系统中存在两个“终端日志”查看界面：
    1. `AccountsView` 底部的内嵌日志：基于每 3 秒 HTTP Polling；
    2. `UnifiedTerminalView` 内部的 `TerminalLogsView`：基于实时 Server-Sent Events (SSE)。
  - 这种双重实现不仅给用户带来“我到底该去哪看服务端报错”的困惑，而且维护了两套互不通气的过滤和复制逻辑。

---

### UX-05: API 调试操场单次性与资产沉淀缺失 (Playground Ephemeral Experience)
- **现象描述**：
  - Playground 当前虽然提供了 4 种预设（基础对话、工具调用、多模态视觉、思考模式），但用户的修改一旦刷新或者切换 Tab，只能依靠 Monaco 的缓存；
  - 缺乏“调试历史记录（Request History）”面板；
  - 缺乏像 Postman / Insomnia 一样的“环境参数与集合（Collections）”机制，无法将一次成功的调试直接保存为常用模板。

---

### UX-06: 翻译工作台对比排版的弹性缺陷 (Translate Comparison Layout Bottleneck)
- **现象描述**：
  - 当在 Compare Mode 下选择 3 个模型（如 Flash / Pro / Lite）时，屏幕被均分为 3 列；
  - 在中等分辨率屏幕（如 13 寸笔记本或 iPad）上，每列宽度不足 300px，长行代码块和复杂 Markdown 产生严重水平滚动条；
  - 缺乏左右文本的对齐比对功能（Diff 模式），对比翻译差异全靠肉眼逐行扫描。

---

### UX-07: 反馈体系与边界状态不完备 (Inconsistent Feedback & Edge States)
- **现象描述**：
  - **空状态**：当没有任何账号、没有任何日志、搜索结果为 0 时，界面多直接显示简单的灰底文字（如 `No Data`、`未找到符合条件的账号`），缺乏引导性插画、清空筛选按钮或一键创建行动项（Call to Action）。
  - **报错提示**：有的地方使用 Red Text 注入（如登录页），有的地方使用自制定时销毁的 Toast（如 AccountsView），有的地方直接静默 catch。
  - **加载态**：加载过程中缺乏骨架屏（Skeleton Screen），页面数据突变导致界面发生明显的布局位移（CLS）。

---

## 3. UX 改进目标与北极星指标

重构后的系统应达到以下专业级交互体验指标：
1. **即时排障（Time-to-Diagnosis）减少 60%**：支持在 Logs 中通过 URL 直达特定错误日志，并通过多维度组合筛选（耗时/模型/状态）秒级定位。
2. **零认知混淆（Zero Duplication）**：砍掉 Accounts 内嵌轮询日志，统一到全局终端与实时日志抽屉；收敛所有 Modal 为标准弹窗规范。
3. **沉浸式调试（Zero Disruption）**：Playground 引入本地会话历史，调试现场自动保存。
4. **全端平滑响应（Fluid Multi-Device）**：PC 保持高效桌面工作台，移动端与平板采用标准自适应抽屉与底部触控优化。
