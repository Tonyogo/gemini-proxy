## 一、 背景与总体目标

本项目最初为一个集成了 **Claude/Gemini 协议代理** 与 **基于 WebSocket/PTY 的多主机远程运维 WebTerminal / Agent** 的复合系统。为了将代理服务迁移到无状态、高并发、全球 CDN 加速的 **Cloudflare Workers (Serverless)** 边缘网络上，必须解决以下核心架构冲突：
1. **解决 Serverless 运行障碍**：V8 Isolate 边缘环境不支持 Node.js 原生 C++ 编译扩展（`node-pty`）、长链接单机内存状态（WebSocket Hub）以及本地磁盘文件持久化（`fs` 日志落盘与配置读写）。
2. **职责分离与轻量化**：将 Terminal 终端运维系统彻底抽离为独立项目，让 `gemini-proxy` 专注于高性能无状态的 LLM 协议转换。
3. **实现双模边缘架构**：引入轻量 Web 标准框架（Hono），保留原生 Node.js/Express 运行能力的同时，支持一键发布到 Cloudflare Workers，并支持 Cloudflare KV（动态配置）与 R2（交易审计日志）。

## 二、 改造工作回顾与交付清单

### 1. 第一阶段：Terminal 模块彻底解耦与剥离 (`feat/extract-terminal-module`)

#### A. 后端与服务解耦
* **彻底删除 `src/terminal/` 目录**（共 12 个文件：HostManager、FileService、ExecService、WebSocket Hub、PTY Bridge 等）。
* **卸载底层依赖**：移除了 `node-pty`、`ws` 以及 `@types/ws`，项目彻底脱离 C++ 编译环境（如 python, make, g++）要求，`npm install` 速度显著提升。
* **清理服务入口**：
  * `src/app.ts` / `src/index.ts`：移除 WebSocket upgrade 监听，移除 `/api/terminal/*` 路由及 `/install.sh` / `/gt` 脚本直链下载端点。
  * `src/utils/logger.ts`：移除向内部终端广播日志的逻辑，保留标准控制台输出。
  * `src/proxy/controllers/` 与 `src/utils/upstreamManager.ts`：移除 Agent Egress 代理及内部 `terminalHostManager` 耦合，删除 `src/proxy/services/agentProxyService.ts`。

#### B. 前端界面精简
* **删除终端组件与手势库**：
  * 移除 `frontend/src/components/terminal/` 全部文件（文件管理器、手势工具栏、主机选择器、图片预览）。
  * 移除 `WebTerminalView.tsx`、`UnifiedTerminalView.tsx`、`TerminalLogsView.tsx`。
  * 移除移动端视口补偿、IME 辅助输入、放大镜、按键编码等 6 个工具文件。
* **卸载 `@xterm/*` 依赖**：移除 `@xterm/xterm`、`@xterm/addon-fit`、`@xterm/addon-web-links`，打包体积缩减数兆。
* **重构导航与视图**：
  * `App.tsx` 与 `DiscoverHubView.tsx` 清理 `#terminal` 路由和在线终端/系统日志卡片。
  * `AccountsView.tsx` 与 `ConfigModal.tsx` 移除终端日志轮询与 Agent 选项。

#### C. 测试套件与 CI/CD 改造
* 清理了 60+ 个终端与 PTY 相关的陈旧测试用例（清理约 9,200 行测试代码）。
* 更新 `.github/workflows/deploy.yml`：改为从外部独立的 `TERMINAL_SERVER` 动态下载 `gt` CLI 进行远程部署，解除自引用的发布死锁。
* **产出独立项目指南**：编写 `docs/gt-server-bootstrap/README.md`，完整记录独立运维项目 `gt-server` 的抽取和初始化方法。
* **成果**：净删除代码 **22,677 行**，全部 95 组测试套件（498 tests）100% 通过。

### 2. 第二阶段：Cloudflare Workers 边缘代理架构落地 (`feat/cloudflare-workers`)

基于**双模并行运行（选项 A）**与**完整支持 KV 动态配置与 R2 交易日志持久化，含全量 Admin 重构（选项 B）**实现。

#### A. 核心目录与模块划分
新增�� `worker/` 目录，完全基于 Web Standard API 构建：

```text
worker/
├── index.ts                  # Worker 主入口（全局 CORS、SPA 静态兜底、路由挂载）
├── env.ts                    # Cloudflare Bindings 类型定义 (CONFIG_KV, LOGS_BUCKET, ASSETS)
├── config/
│   └── workerConfig.ts       # 边缘动态配置管理中心（支持 env 与 KV，带 15s 内存缓存防穿透）
├── services/
│   ├── workerLogger.ts       # 异步交易审计日志（基于 R2 与 ctx.waitUntil，支持详情与分页读取）
│   ├── workerStream.ts       # Web Standard TransformStream 实时流式转码管道（Gemini SSE -> Claude SSE）
│   └── workerUpstream.ts     # 边缘负载均衡、熔断器与 Direct 模式多 Key 轮询调度器
├── utils/
│   └── requestHelper.ts      # 请求头提取、敏感 API Key 脱敏、超时解析
└── routes/
    ├── claudeRoutes.ts       # /v1/messages（流式/非流式/思考模型）、/v1/models、/v1/messages/count_tokens
    ├── geminiRoutes.ts       # /v1beta/* 原生透传与 thinking 增强
    └── adminRoutes.ts        # 全量 /api/admin/* (状态、配置热重载、R2日志回放、多账号转发)
```

#### B. 关键技术亮点
1. **核心转码引擎 100% 共享复���**：
   * 原生 `claudeTranslator.ts` 纯数据结构清洗转换逻辑完全复用，无需重写。
2. **纯 Web Streams 管道架构（Zero Node Stream）**：
   * 在 `workerStream.ts` 中完全采用 Web 标准 `TransformStream` 进行逐行切片缓冲与 JSON 解析，实时输出 Claude SSE 标准事件，彻底消除 Node.js 事件监听和流内存泄漏隐患。
3. **KV 动态配置热重载（WorkerConfig）**：
   * 静态默认值从 `wrangler.toml` 的 `[vars]` 读取；
   * 绑定 `CONFIG_KV` 时，从 `runtime_config` 读取配置覆盖，内置 15s 内存缓存防穿透；管理后台保存配置时即时写入 KV，全球边缘秒级同步。
4. **R2 交易日志持久化与控制台回放（WorkerLogger）**：
   * 响应客户端后通过 `c.executionCtx.waitUntil()` 异步写入 R2 对象存储，完全不阻塞首字延迟（TTFT）；
   * 完整支持前端 Chrome DevTools 风格的审计面板（时间树结构、按小时筛选、分页、JSON 详情回放）。
5. **全量 Admin 与多账号管理接口**：
   * 实现了 `/api/admin/status`、`/api/admin/config`、`/api/admin/models`、`/api/admin/stats`；
   * 实现了 `/api/admin/accounts/*`（Direct 直连模式自动解析配置的多 Key 与统计，Proxy 模式透明代理转发）。
6. **前端单页应用（SPA）静态资源托管**：
   * `wrangler.toml` 绑定 `[assets]` 指向 `./dist/frontend`，根路径与客户端路由均由 Cloudflare CDN 极速分发。
7. **防御性自动降级机制**：
   * **未绑定 KV 时**：配置回退到环境变量，管理后台修改保存在临时内存中；
   * **未绑定 R2 时**：日志写入自动静默跳过（No-op），核心 API 代理 100% 正常运行且延迟最低。

## 三、 运行与部署操作指南

### 1. Node.js 原生模式（VPS / Docker / PM2）
原有运行流程保持 100% 不变：
```bash
# 安装依赖与构建
npm install
npm run build

# 本地开发
npm run dev

# 运行测试
npm test

# 生产启动 (PM2)
pm2 start ecosystem.config.js
```

### 2. Cloudflare Workers 边缘模式

#### A. 本地开发与联调
```bash
npm run dev:worker
# 启动本地 wrangler 模拟环境，默认监听 http://localhost:8787
```

#### B. 首次发布到 Cloudflare
```bash
# 1. 登录 Cloudflare 授权
npx wrangler login

# 2. 一键构建前端并发布
npm run deploy:worker

# 3. 设置后台管理密钥（Secret）
npx wrangler secret put ADMIN_SECRET_KEY
```

#### C. （可选）开通持久化存储（KV 与 R2）
若需要网页端保存配置与审计日志：
```bash
# 1. 创建 KV 命名空间
npx wrangler kv namespace create CONFIG_KV
# 将返回的 id 填入 wrangler.toml 的 [[kv_namespaces]]

# 2. 创建 R2 存储桶
npx wrangler r2 bucket create gemini-proxy-logs
# 在 wrangler.toml 中取消 [[r2_buckets]] 的注释

# 3. 重新部署
npm run deploy:worker
```

#### D. 实时监控排查
```bash
npx wrangler tail
# 实时捕获经过 Worker 的请求路径、状态码和耗时日志
```
